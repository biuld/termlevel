# 多终端平铺设计

状态：第一版核心交互已实现，持续日用人工验收待完成。日期：2026-11-13。

本文记录多 terminal 同时展示的定向分屏方案及当前实现。保留现有垂直标签和分组；代码所有权见 [架构](architecture.md)，证据见 [验证记录](validation.md)。

## 目标与范围

用户可以同时运行和查看 shell、开发服务、测试、agent 等会话，明确知道键盘输入发往哪个 terminal，并通过鼠标或键盘调整布局。

第一版提供：

- 当前 pane 向右、向下分屏，以及在其他方向放入已有会话。
- 方向焦点、交换位置、调整尺寸、均分布局。
- 临时放大与还原，收起 pane 与关闭 terminal。
- 从侧栏拖入已有会话，以及 pane 之间的拖放。
- 多 pane 下的标题、退出状态、响铃、输入法和焦点隔离。

第一版不加入自动主窗与栈、滚动式无限画布、浮动 terminal 窗口、pane 内嵌套标签栏、多窗口共享同一个 session、广播输入或布局预设管理。布局持久化单独推进；本方案不提供应用重启后的活会话恢复。

UI 继续使用 NSH 0.5.0 的 macOS 原生后端。PTY、终端输出、网格及高频绘制继续由 Rust 管理。

## 交互方向

参考平铺 WM 的定向分割、方向焦点、位置交换和临时放大。具体参考 [i3 的使用与布局说明](https://i3wm.org/docs/userguide.html#_using_i3)；快捷键和应用内交互按终端场景重新设计。

| 方案 | 特点 | 本方案选择 |
|---|---|---|
| 定向分屏 | 切分当前 pane，用户安排的位置和比例保持稳定 | 第一版采用 |
| 主窗与栈 | 一个主 pane，其余会话自动排列在旁边 | 后续候选；新增会话容易改变多个 pane 的尺寸 |
| 滚动画布 | 宽度不足时将部分 pane 放到视口之外 | 后续候选；增加可见性、导航与滚动规则 |

典型布局：左侧保留主要工作终端，右上运行服务，右下观察测试。

```text
┌───────────┬────────────────────┬───────────────┐
│ Sessions  │ Shell              │ Dev server    │
│           │                    │               │
│ Shell     │                    ├───────────────┤
│ Server    │                    │ Tests         │
│ Tests     │                    │               │
└───────────┴────────────────────┴───────────────┘
```

这是一个窗口内的布局。一个标签组就是一块平铺工作区：画布只展示当前组的布局树，组与组不会出现在同一画面。未分组和固定标签共用另一棵树。折叠、改名和组内排序不改变该组的布局；切到别的组会换成那一组自己的树，再切回来时比例、放大和 pane 都还在。

两个及以上 pane 在侧栏里合成一个分屏单元，样式是圆角卡片。卡片里的标签就是这些 pane，数量不能超过画面放得下的分屏数，也不另收隐藏标签。仍在画面上、但不是焦点的标签，在行尾垂直居中放一枚圆点；悬停或键盘焦点时圆点让给关闭按钮，不占行的右上角。这个单元可以单独待在侧栏里，也可以从其中一个标签的「移到组」整块移进一个标签组；卡片上不单设菜单，移进去不新建组。已经在组里时，分屏留在该组的卡片中，组里没参与分屏的标签仍排在卡片外面。侧栏把别的组的标签拖进当前画面，表示把它加入当前组并按落点分屏或替换。菜单里的「在右侧 / 下方显示已有终端」只列出当前组的会话；选择别的组的标签会切到那一组，而不是把两组拼到一起。取消分组时，如果未分组工作区还没有布局，就接手这一组的树；未分组已经有布局时，只把当前看着的终端放进去。

## 会话、tab、pane 与焦点

| 概念 | 身份与职责 |
|---|---|
| Session | Rust 持有的 PTY、进程、网格、输出及状态，使用稳定 session ID |
| Tab | 侧栏中的会话条目，继续使用 session ID，不改成布局容器 |
| Pane | 布局中的展示位置，使用独立、稳定的 pane ID，引用一个 session ID |
| Split | 布局中的二叉分割节点，保存方向、两个子节点和比例 |
| 布局焦点 | `focusedPaneId`，决定当前会话、菜单操作目标和输入焦点恢复目标 |
| 原生输入焦点 | 当前 AppKit Input 是否真正持有键盘；打开菜单、弹窗或切换应用后可以暂时没有 |

核心不变量：

1. 一个 session 在当前窗口的布局树中最多出现一次。
2. 多个 pane 可以同时显示和接收鼠标操作；同一时刻最多一个 terminal 接收键盘输入。
3. 非空布局必须有且只有一个逻辑焦点 pane。弹窗可以暂时拥有实际输入焦点。
4. 侧栏当前选中的 session 从焦点 pane 派生，不能另维护一份可能不同步的选择状态。
5. 分屏、交换、缩放、放大和收起均不重建或结束已有 Rust session。
6. 关闭 terminal、关闭所属分组、关闭主窗口、退出应用，以及 shell 以退出码 0 结束，才进入现有会话关闭通路。
7. 布局树不保存终端字节流、cell grid、进程 PID 或输出副本。

## 侧栏与会话切换

| 入口 | 结果 |
|---|---|
| 点击当前组里、布局中已有的 tab | 整个右侧换成这一组分屏，并聚焦对应 pane |
| 点击当前组里、布局中没有的 tab | 整个右侧换成这个终端。组里已有分屏时，分屏树保持不动，再点回分屏中的标签会整块回来 |
| 点击其他组的 tab | 整个右侧换成那一组：已在其分屏中则显示整组分屏，否则只显示这个终端 |
| 搜索并选择会话 | 使用与点击 tab 相同的规则 |
| `⌘1…⌘9`、Ctrl+Tab 等现有会话切换 | 使用同一选择操作；不会隐式新增 pane |
| `⌘T`、现有全局新建入口 | 新建 session 并选中它，整个右侧换成新终端。已有分屏留在侧栏 |
| 没有布局时选择或新建会话 | 建立一个 pane，并取得焦点 |

“新建终端”与“分屏新建终端”是两个明确动作。现有全局新建的分组规则不变；分屏新建则归入当前 pane 会话的分组，新 terminal 不继承固定状态。

初始目录使用当前会话记录的启动目录，不能显示或声称它是 shell 的实时 cwd。未来接通 shell integration 后再扩展这个来源。

侧栏继续只突出当前焦点 session。其他已展示会话使用轻量的 pane 标记及 tooltip“已在布局中显示”，不增加第二层选中底色。收起态通过图标旁的小标记及无障碍说明表达，原生验证其辨识度。分组折叠仍保留，选择其成员时沿用现有自动展开规则。

## 分屏与尺寸

“向右分屏”将当前 pane 变为左右两部分，旧会话在左，新会话在右；“向下分屏”将旧会话放在上方，新会话放在下方。新 pane 取得焦点，默认各占一半。

工具栏或菜单同时提供“在右侧显示已有终端…”和“在下方显示已有终端…”。若所选 session 已经在布局中，直接聚焦它；调整它的位置通过拖放完成，避免出现同一 session 的两个视图争用 PTY 尺寸。

分屏前先验证尺寸，再创建 session。`Sessions.open` 返回启动失败记录时，新 pane 保留明确错误状态并允许关闭或重新选择其他会话，不悄悄创建第二个 shell。

尺寸规则：

- pane 之间沿用 `gap-pane`，当前为 8 pt；外层不额外嵌套圆角容器。
- 拖动间隙调整最近的一条分割边界，不移动侧栏宽度。
- 比例属于 Split，保存为浮点比例；布局计算按实际原生 bounds 分配最终尺寸。
- 候选最小正文尺寸为 40 列 × 8 行，按字体实际 cell 尺寸计算，并加上 pane 工具栏、左右和底部内边距。该值是原型起点。
- 新分割无法同时满足两个子树最小尺寸时，禁用该操作，并说明可以替换当前会话或先收起其他 pane。
- 双击分隔间隙将对应 Split 恢复到可行范围内最接近 1:1 的比例。“均分布局”递归执行同样操作。

缩小窗口、增大字体或展开侧栏可能让已有布局不再满足最小尺寸。优先在约束内调整实际比例，不覆盖用户保存的比例；若仍无法容纳，临时仅展示焦点 pane，并提供“窗口过窄，仅展示当前终端”的说明。树及其他会话保留，空间足够后恢复布局。第一版不偷偷删除 pane，也不将终端缩小到无法操作。

## 焦点与键盘

鼠标点击 pane 的标题或正文时，更新逻辑焦点并将输入交给对应 terminal。鼠标经过其他 pane 不改变焦点。滚动未聚焦 pane 只滚动其内容，不抢键盘；文字选择和右键菜单的原生行为需单独验证。

方向导航按当前 pane 的实际几何位置寻找邻居：优先选择在指定方向、且垂直于移动方向的投影与当前 pane 重叠的候选，再比较边界距离、中心距离，以稳定 pane ID 作为最终平局规则。没有邻居时保持原位，不绕回另一侧。

方向交换使用同一个邻居规则，只交换两个 pane 引用的 session，pane ID 和分割比例不变。焦点跟随原来的 session 到新位置。

当前 macOS 快捷键如下，菜单保留所有操作入口。AppKit 在组合输入期间优先将按键交给输入法，工作区快捷键此时可能不执行。

| 动作 | macOS 快捷键 |
|---|---|
| 向右分屏新建 terminal | `⌘D` |
| 向下分屏新建 terminal | `⌘⇧D` |
| 聚焦相邻 pane | `⌘⌥方向键` |
| 与相邻 pane 交换 session | `⌘⌥⇧方向键` |
| 临时放大 / 还原 | `⌘⇧Enter` |
| 关闭当前 terminal | 沿用 `⌘W` |

键盘缩放通过菜单进入“调整尺寸”模式：方向键调整对应祖先 Split，Enter 或 Escape 退出。期间显示可见提示，方向键不发往 shell；步长为对应分割比例的 4%。

Control 组合键继续优先保留给 terminal；不直接复制 WM 的快捷键表。对话框、菜单和组合输入有各自的焦点优先级。

## 拖放

拖 pane 只能从标题栏开始，拖终端正文继续用于选择文本。侧栏内部拖动继续负责 tab 排序及分组；只有进入右侧 pane 区域后，才显示布局放置提示。

| 来源与落点 | 结果 |
|---|---|
| 当前组里隐藏会话的 tab → pane 边缘 | 切分目标 pane，将已有会话放入所示方向 |
| 当前组里隐藏会话的 tab → pane 中央 | 替换目标 pane 的 session；旧会话保留 |
| 其他组的 tab → pane 边缘或中央 | 该终端加入当前组，再按落点分屏或替换；原组的布局去掉它 |
| 已展示会话的 tab / pane 标题 → 另一 pane 中央 | 交换两个 session，焦点跟随拖动的会话 |
| 已展示会话的 tab / pane 标题 → 另一 pane 边缘 | 移除来源叶子、合并原分支，再切分目标 pane 插入来源 pane |
| 拖到自身或窗口外 | 不改变布局 |

从布局移动 pane 时保留其 pane ID。边缘插入需要在移除来源之后重新计算目标约束，避免用旧尺寸错误判断能否分割。拖动本身不修改 session 的分组、固定状态或侧栏顺序。

预览要求：

- 中央显示交换或替换提示，边缘显示实际预计占据的半区。
- 不可放置的位置显示禁用反馈，不在松手后突然降级为替换。
- 拖动过程只改变预览；松手后一次性提交树、焦点与 session 分配。
- Escape、拖出窗口、失去拖动捕获均取消，恢复原布局。
- 放大或过窄临时展示状态下，先还原到可展示的完整布局才能开始 pane 拖放；空间不足时保留菜单替换入口。

第一版只支持目标 pane 四边，不支持“整个画布边缘插入”或拖动父容器。边缘命中带为目标 pane 宽 / 高归一化距离的 24%，角落取最近边，其余为中央区域。

## 放大、收起与关闭

临时放大是窗口内容区内的展示模式，不进入 macOS 全屏。布局树、比例及 pane ID 不变；还原后恢复原位置。聚焦另一个已有 pane 时，放大目标随焦点切换。修改布局的分屏操作先退出放大，再按原 pane 位置执行；若空间不够则拒绝操作。

放大状态下其他 pane 的逻辑位置保留，但暂时隐藏、禁用命中并移出无障碍遍历。隐藏视图不向 PTY 发送 0×0 resize，保留最后的有效网格尺寸。

“收起 pane”只删除对应布局叶子并合并其父 Split，session 留在侧栏继续运行。只剩一个 pane 时禁用收起，避免出现“有会话但没有任何内容”的无说明状态。

“关闭 terminal”沿用现有结束进程的语义：

1. 显式关闭对应 session，移除 tab 以及它在树中的叶子。
2. 若关闭的是焦点 pane，优先聚焦被合并的兄弟子树中的最近 pane；其后才考虑其他 pane。
3. 若树已空但侧栏还有其他会话，选择最近使用的剩余会话，建立一个 pane。
4. 若全部会话已关闭，显示现有空工作区，不自动开启 shell。

关闭非焦点 session 不抢焦点。关闭分组时，将相关 session 作为一次工作区操作统一从布局中移除并归一化；避免逐个关闭过程中短暂选中一个也即将关闭的 session。

Shell 以退出码 0 结束时，标签和 pane 一起关闭，与 ⌘W 相同。Ctrl+D 在空行上就是这条路径。非 0 退出或启动失败保留 pane 和输出，并显示退出码或错误，不自动合并或新建。pane 标题栏的移除操作明确标为“收起 pane”；“关闭 terminal”放在会话菜单中，避免同一个 × 同时代表两种行为。

## 视觉与状态反馈

沿用当前 Fleet Dark / Light 配色、12 pt pane 圆角和 8 pt 间距。每个 terminal pane 都有自己的紧凑工具栏；不在外面再套一层通用 terminal 卡片。

- 工具栏显示会话名与必要的目录提示，完整初始目录放在 tooltip 或菜单中。窄 pane 优先保留可区分的会话名。
- 仅焦点 pane 使用 1 pt 主题焦点色描边，采用不占据布局尺寸的绘制方式；其他 pane 不整体降亮度。
- 属于标签组的 pane 在标题前显示该组的色标。侧栏里，当前布局所属的组有一层浅底，无障碍说明带 “current layout”。
- 终端正文顶部不增加内边距，左右和底部延续现有 16 pt。
- 分隔线平时隐藏，间隙在悬停和拖动时显示低对比缩放反馈。
- 放大态显示可发现的“还原布局”操作；过窄临时展示与用户主动放大使用不同说明。
- 非焦点 terminal 响铃时，在侧栏和该 pane 工具栏显示标记；聚焦后清除。已经可见不等于用户已关注。
- 主题变更同时更新所有可见 pane 的默认颜色和控件，保留程序 ANSI / truecolor 语义。

窗口顶栏继续唯一负责窗口级操作和拖动窗口。pane 标题负责焦点和 pane 拖放，两者不共用 `windowDrag` 行为。

## 状态模型与实现边界

纯布局模块 `ui/tiling.ts` 负责树变换、约束、方向选择及归一化；`ui/workspace.ts` 把会话操作和布局变换组合成一次状态提交。

```ts
type LayoutNode =
  | { kind: "pane"; id: string; sessionId: string }
  | {
      kind: "split";
      id: string;
      axis: "row" | "column";
      ratio: number;
      first: LayoutNode;
      second: LayoutNode;
    };

type TilingState = {
  root: LayoutNode | null;
  focusedPaneId: string | null;
  zoomed: boolean;
};
```

过窄临时展示由树的最小尺寸和实际内容区域推导，不写入 `zoomed`。可见性需要区分：树中已分配的 session，以及当前真正展示的 session。两者均从状态推导，不维护另一份可漂移的列表。

原单终端实现用 `activeId` 同时控制可见性、命中、无障碍隐藏和 `SessionTerminal.active`。多 pane 已将这些职责拆开：

- pane 已展示：可以绘制、滚动、选择和命中。
- pane 为逻辑焦点：决定工作区当前会话、菜单目标和焦点描边。
- 原生 Input 实际聚焦：决定该 session 能否接收键盘输入。
- 弹窗或菜单打开：按已有原生优先级临时转移输入，不让其他 terminal 自动抢回焦点。

`TerminalSurface` 的位置与尺寸由 pane bounds 决定；不能继续让所有可见 surface 都用同一组 `inset: 0`。`SessionTerminal.active` 的现有语义需要检查并收窄为输入授权，而不是用它停掉其他可见 pane 的刷新。

原生挂载方案优先验证稳定、按 session ID keyed 的 surface 层，布局树计算或测量 pane 矩形后分配给对应 surface，避免交换和树归一化时重建 Input、选区和滚动视图。分隔拖动应优先使用 NSH 原生分栏的实时布局。若框架无法同时提供稳定 surface 和实时几何同步，应先做原生技术验证，记录滚动、选区、marked text 是否能保留，再确定挂载方式；不能把“Rust 会话没丢”当成全部 UI 状态已保留。

原生布局尺寸变化继续直接进入 Rust session 的 resize 通路。终端字节流、刷新计时器和网格绘制不经过 TSX。预览 transport 继续明确标识且不执行命令。

## 原子操作与恢复

所有结构操作提交前检查：session 存在、pane ID 唯一、session 引用唯一、Split 两个孩子均非空、比例有效、焦点指向有效叶子。删除后将单子节点 Split 收缩为该子节点。

分屏创建需要处理会话创建和布局提交之间的边界：尺寸预检通过后才调用 `Sessions.open`；如果创建成功但后续布局提交失败，工作区仍必须登记新 session 并给出可恢复入口，不留下侧栏不可见的孤立进程。

布局变换不调用 `Sessions.close`。UI 重挂时可以重新绑定同一 Rust session；布局还未持久化的阶段，应明确退回单 pane 展示，不能凭旧 pane ID 或 PID 声称恢复原布局。以后持久化布局时必须校验 session 引用，并另行定义应用重启时“新开 shell”的恢复策略。

## 验收清单

### 布局与工作区

- 右分屏后再对右 pane 下分屏，产生预期的三 pane 布局；修改其中一个比例不重排无关子树。
- 反复分屏、交换、边缘移动、收起、关闭后，没有重复 session 引用、空 Split、失效焦点或孤立会话。
- 侧栏选中分屏里的标签时，整个右侧是这一组分屏，焦点落在该标签。选中分屏外的标签时，整个右侧换成这个终端，分屏树保留。分组折叠、组内排序和改名不改变该组布局。跨组拖入画面会加入当前组。
- 非焦点会话关闭不抢焦点；关闭整个组只做一次最终焦点选择；最后一个会话关闭后进入空状态。
- 放大 / 还原和窗口过窄 / 恢复都保留树和用户比例。禁用分割在创建进程之前生效。
- 拖放中心、四边、自身、外部、不可行尺寸和 Escape 取消均有明确结果。

### Rust 与真实会话

- 两个及以上 PTY 同时持续输出，各 pane 正确刷新，非焦点输出不会停止。
- 普通输入、粘贴、Ctrl+C 和组合输入只进入目标会话；放大、交换和侧栏替换后同样成立。
- 每个 pane 的 rows / cols 与真实可用正文区域匹配；隐藏和切换展示模式不会向 PTY 发送 0×0。
- 收起、替换、树归一化和视图重新绑定不结束进程、不重放输入、不清空输出。
- 明确关闭 session、关闭组及退出应用继续满足现有终止和回收约定。

### 原生 GUI

- 展开、收起、悬停覆盖侧栏时，布局大小和输入焦点符合规则；覆盖态不意外 resize 终端。
- 在不同 pane 间切换时，真实系统输入法候选窗跟随正确的光标；进行中的组合文本仍归属原会话。
- 调整尺寸、移动 pane 和放大 / 还原后，网格与 Input 坐标原点一致；检查滚动、选择和复制。
- 深浅色和高 DPI 下，焦点边框、响铃、拖放预览、缩放命中区及无障碍标签可区分。
- 比较单 pane 与多 pane 的持续输出性能和资源占用，记录窗口尺寸、session 数、输出负载及测量方法。

实现时使用 `./scripts/nsh check`、`./scripts/nsh test`、`./scripts/nsh build`，在 [验证记录](validation.md) 分别记录类型 / 构建、headless、真实 PTY 和原生 GUI 证据。本文的草图与设计描述不计作实现验收。

## 当前实现说明

- 终端按 session ID 保持在唯一平铺 surface 层，位置与尺寸由当前标签组的树计算。其他组的树保留但不投影。头部工具栏可拖动，正文仍用于文本选择。属于分组的 pane 用该组色标。
- Shell 退出码 0，包括预览和真实会话里的空行 Ctrl+D，关闭对应标签和 pane。非 0 退出留下状态条。
- pane 缩放使用原生 View pan/responder 事件受控更新 TSX 几何，没有将 terminal 放进递归 `ResizablePanelGroup`，以保留 Input、滚动视图与 marked text 的实例。侧栏仍使用原生分栏。拖动期间的布局更新经过 TSX，不能声称完全绕过 JS。
- `TerminalMetrics` 与 Rust 网格使用相同的字体测量函数。约束采用 40 列 × 8 行，加工具栏和宿主内边距，字体更换后重新测量。
- 临时放大只改变投影；过窄提示常驻，空间恢复后自动还原。只有实际展示的 pane 参与命中和无障碍遍历。
- `scripts/test-native-tiling` 覆盖 AppKit 视图、组合文字随 pane 移动、候选锚点、提交归属与布局恢复。marked text 移动测试通过 fixture 调用同一个工作区交换操作；普通方向快捷键另行断言，不把两种证据混为一谈。
- fixture 可向 `WorkspaceApp` 注入同一个工作区模型，控制会话及测试动作；生产入口仍自行创建工作区。布局未持久化，重挂工作区仍退回单 pane 绑定。
