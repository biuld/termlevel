# UI 与主题

## 设计方向

采用用户选定的第二版「侧栏贯顶」。侧栏从窗口顶部延伸到底部；右侧只有一行会话工具栏和终端内容。

- 全高侧栏默认 208 pt，可调范围 176–288 pt，收起为 44 pt。
- 左上是系统窗口按钮与侧栏开关。右侧会话工具栏与它们同高，均为 36 pt；不再额外叠一条全窗口标题栏。
- 侧栏收起时，顶部切换为横跨窗口的完整工具栏，通过 `titleBar().left/right` 为真实系统按钮预留空间；44 pt 图标栏从工具栏下方开始，不再在窗口按钮之间画分栏边界。展开态仍为侧栏贯顶。终端在同一棵树中保留，不随工具栏位置切换而重建。
- 固定标签与普通标签均为 28 pt 单行布局，只显示图标和名称。移除固定卡片、目录副标题和大图标底座。
- 分组使用纯色标记、组名与细引导线。标记左下角为 3 pt 小圆角，其余为半圆；不含文件夹图案。展开时标记 14 pt，标题 12 pt、中等字重、使用中性正文色；颜色集中在组标，细引导线降低对比，单行省略，整行高 28 pt。数量移入组头 tooltip，更多按钮仅在悬停、键盘焦点或编辑期间显示。
- 收起侧栏时，组标仍是展开态的 14 pt 标记，在行内居中，左侧低对比 1 pt 颜色线串起整组。折叠组保留当前选中的标签，其余标签用 `+N` 圆形计数入口表示；点击计数展开组。切换到组外时计数包含全部隐藏标签。
- 鼠标移入收起的侧栏时，以浮层展开至保存的侧栏宽度，覆盖终端而不挤压内容；移出后收回。分组编辑浮层打开期间保持展开，手动展开侧栏仍使用固定分栏布局。
- 收起状态（含悬停浮层展开）禁用分界拖动，使用普通光标，不显示拖动悬停高亮；只有手动固定展开时允许调整宽度。
- 搜索、新建分组、设置收至侧栏底部，旁边显示会话数量，不额外画横向分隔线；新建终端保留列表入口和工具栏按钮。
- 终端直接铺满右侧剩余空间，取消外边距、嵌套圆角面板、阴影和常驻状态栏。上边不留白，滚动文字裁切在会话工具栏下沿；左右和底部仍使用 `padding-terminal`。
- 右侧 36 pt 行只负责对齐窗口按钮和拖动窗口，底色与终端相同，不画成第二条标题栏。会话名只出现在标签上。目录、新建和更多直接排列在右上工具栏，不设置独立底座；窄窗口隐藏目录。侧栏收起时，展开按钮是左侧单独的圆钮，与展开态使用同样的无底色常态和悬停反馈。预览身份仍由终端欢迎信息与设置说明明确展示。
- UI 正文 12 pt，终端默认字号 13 pt；图标按钮 26 pt、操作按钮 28 pt、输入框 30 pt。
- 对话框继续使用 `m-auto` 居中，保留紧凑尺寸与 Escape 关闭。对话框本体保持实色 `bg-popover`，底下是均匀遮罩，不用玻璃。
- 设置支持 System / Light / Dark，默认跟随系统；主题切换及所有导航操作保留终端实例。

## 表面与层级

应用自定义界面统一使用实色表面，不设置 Liquid Glass、背景模糊或平台半透明材质。

- 固定展开、收起和悬停展开的侧栏都使用不透明 `sidebar`，底色接近终端，仅保留轻微明度差。悬停展开时不改变底色，只通过右侧圆角、细边框与轻阴影表达覆盖关系。
- 固定展开态仅保留低对比分界，收起态分界透明。两种固定状态均不加阴影。
- 会话工具栏底色与终端一致。目录和按钮直接放置在工具栏上，不设置胶囊底座；按钮保留悬停、按下与键盘焦点反馈。
- 分组编辑浮层和 tooltip 使用不透明 `popover`，搭配 `border` 细边框、`radius-overlay` 圆角和轻阴影。
- 选中标签保持实色胶囊，终端保持 `terminal-background`。对话框下方的均匀遮罩仅用于表达模态，不做背景模糊。

## 分组编辑

参考 Firefox 的分组编辑浮层：右键组头或点击更多按钮，在组头旁打开 `GroupEditor`，不再通过原生子菜单选颜色或另开重命名对话框。

- 顶部为九个颜色圆点：蓝、紫、青、橙、黄、粉、绿、灰、红；当前颜色带选中环，配色仍来自主题。
- 下面直接编辑名称，输入即时更新组名；未命名组显示 `未命名分组`，也用于可访问名称及菜单标签，输入框仍保持空值。
- 新建组默认蓝色、名称为空，直接打开同一个编辑浮层。
- 提供组内新建终端、取消分组和删除组；取消分组保留终端，删除组需要确认并关闭组内终端。
- 输入框 Enter 或 Escape 关闭浮层，点击外部也关闭。选色后保持输入焦点；关闭不会回滚已经修改的名称或颜色。
- 浮层锚定整个组头，随其滚动、收放而定位，由 NSH `Overlay` 处理屏幕边缘约束；宽 280 pt，维持紧凑密度。
- 浏览器的链接、AI 推荐、保存组、多窗口等操作没有作为占位入口加入当前原型。

## 配置入口

`nsh.json` 的 `theme` 指向 `theme.json`，`appearance` 为 `system`。

`theme.json` 是应用设计值的唯一入口：

| 分类 | Tokens |
|---|---|
| 基础 | `background`、`foreground`、`primary`、`border`、`muted-foreground` |
| 窗口与导航 | `sidebar-*`、`height-titlebar`、`width-sidebar` |
| 标签与控件 | `tab-selected-*`、`tab-hover`、`control-hover`、`control-pressed`、`control-selected-*` |
| 分组 | `group-purple` 等，以及各自的 `-muted`、`-line` |
| 终端 | `terminal-background`、`terminal-foreground`、`terminal-cursor`、`font-mono` |
| 字体与密度 | `font-sans`、`text-*`、`height-*`、`padding-terminal` |
| 圆角 | `radius-control`、`radius-tab`、`radius-panel`、`radius-dialog`、`radius-overlay` |

`cssVars.theme` 放共用字体与尺寸，`cssVars.light` / `dark` 放完整配色。两个外观的自定义 token 名必须一致。

## 使用规则

TSX 静态样式用语义类：

```tsx
<View class="bg-sidebar rounded-(--radius-tab)">
  <Text class="text-sidebar-foreground text-(length:--text-body)">Terminal</Text>
</View>
```

Canvas 和动态样式读取 `token()`，不复制具体色值。分组数据保存 `purple` / `blue` 等稳定标识，`ui/theme.ts` 将标识映射到主题 token。更换主题后，既有分组也随之更新。

所有居中弹窗在 `Dialog` 的 `class` 中设置 `m-auto`。该属性作用于弹窗本体；NSH 不会自动将固定宽度的弹窗居中。

主题不负责会话和工作区状态；切换外观通过 NSH `setColorScheme()`，不卸载或重新创建终端。UI 主题控制终端默认文字、背景、光标和字体，程序通过 ANSI 指定的颜色保持程序语义。预览的品牌与提示符从主题生成 ANSI 色值；已经写入的 truecolor 字符不会因换主题被重写。

调整主题后运行 `./scripts/nsh build` 生成 token 类型声明，再运行 `./scripts/nsh check`。不要手改 `.nsh/types`。原生平台视觉、输入法与选区仍需单独验收。
