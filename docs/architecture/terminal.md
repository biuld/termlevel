# Terminal architecture

Terminal streams, grids, parsing and high-frequency rendering stay in Rust. TSX receives only bounded, low-frequency metadata. This document covers the terminal data path, terminal identity, scrollback history and cross-screen selection, the platform boundary, lifecycle and concurrency, current capability limits, and the libghostty-vt Rust wrappers. Workspace composition and tiling are in [workspace.md](workspace.md); OSC status semantics and UI are in [OSC integration and terminal status](../design/osc-status.md).

## Data path

The default path uses the official `libghostty-vt =1.0.1` C ABI through a standalone Rust wrapper and a SHA256-verified prebuilt macOS static library. The application no longer depends on `alacritty_terminal`. `portable-pty =0.9.0` creates the PTY and child process.

```text
TSX workspace ── open / close / list / shutdown ── Rust SessionManager
                                                   │ strongly owns
                                     PTY + child + Ghostty terminal state
                                        │                 │
                               reader raw bytes ──────────┘
                                        │
                               Rust revision → native view (coalesced refresh)
                                        │
                               Ghostty RenderState → fixed grid / cursor / Ghostty selection
                                        │
                               NSH native input → writer → PTY

Rust → TSX: title, running/exited/error state, bell, OSC 7501 program status summary,
OSC 9;4 progress, OSC 7 live directory, OSC 22 mouse shape and OSC 133 prompt state;
no terminal chunks or cell grid
```

OSC per-item inventory, status business rules, and UI / UX are in [OSC integration and terminal status](../design/osc-status.md). The safe wrapper registers `GHOSTTY_TERMINAL_OPT_PROGRESS_REPORT` and `GHOSTTY_TERMINAL_OPT_PROGRAM_STATUS` and copies bounded owned text inside the callbacks. `Session` holds the full OSC 7501 id record table; `SessionInfo` carries only an aggregate summary, avoiding cloning the whole table on the 16 ms poll. 7501 records retain the state generation and read flag, and acknowledging a version does not delete program facts: blocked stays visible, and read done/error records no longer participate in aggregation. Rust's `TerminalStatusInfo` unifies lifecycle, activity and real progress and carries the runtime `agentApp` separately from the representative record's `app`, so the sidebar, tooltip and accessibility no longer derive them separately; `shellPhase` distinguishes a missing integration from known phases.

Registering the program status callback makes libghostty-vt answer `OSC 7501;?` queries through the registered write-PTY, so programs believe the terminal supports the protocol. Progress percentages are merged and published in Rust. Restart does not restore this runtime metadata. OSC 7's live directory is written to `SessionInfo.currentCwd`; the UI uses the runtime `Tab.liveCwd` for display and search, and saving the document writes `cwd: liveCwd ?? cwd`, so the next start uses the last directory without a schema change. OSC 22 mouse shape and OSC 133 prompt state are also runtime metadata.

Each session has its own Ghostty terminal, persistent parser, native RenderState and Rust frame cache. The default displayed history is the latest 10,000 lines, adjustable from 1,000 to 100,000 in steps of 1,000; the alternate screen has no history. Ghostty reclaims pages underneath, so physical storage may retain one extra page. The safety layer records the logical start with a tracked grid reference per screen, making the displayed cap exact; shrinking and then growing the history does not resurrect discarded lines. The scrollback limit persists with the workspace document.

The reader feeds raw bytes into the same Rust/C parser, preserving UTF-8 and escape state across chunks. The active screen generates a RenderState frame with independent memory on demand; the fixed grid copies only the current window's rows, and the history anchor is maintained by Ghostty's tracked reference across reflow and eviction rather than copying the full history per output chunk. Wide and combining characters keep column coordinates, and adjacent ASCII runs with the same style are merged. All terminal bytes, grids, history and matching stay in Rust.

For ⌘F, ASCII queries use Ghostty's stepwise feed/tick and preserve native soft-wrap matching; Unicode queries copy rows in batches and match lowercase outside the lock. At most one batch is processed at a time, and after output changes the search waits for a 150 ms quiet period before rescanning, rather than scanning everything under the drawing snapshot lock. The low-frequency SearchChange sends only query, count, index and searching; the find bar shows `Searching…`, and an asynchronous completion does not overwrite a different query. New output does not force a jump to a hit. Product preview creates no terminal session. ⌘K still searches sessions by title, directory and group.

Program-specified ANSI / 256-color / truecolor and OSC palette overrides keep their semantics; unspecified colors follow the theme. NSH's base 256 colors are written into Ghostty's default palette, and theme values are written as the default foreground / background, so program overrides are not erased by theme changes. Colors, cursor and device protocol replies go back to the writer directly through Rust. Character-size queries have actual rows / cols; NSH only has point measurement here, not device pixel size, so pixel replies remain 0.

Synchronized output is captured at exact boundaries by the native mode 2026 callback, together with the visible screen and screen identity. A mounted bottom-following surface may advance to the full frame saved at the hold start boundary; the same boundary reuses the Arc, while the history window stays frozen. Initial binding also displays the held frame and does not sample the live screen mid-transaction. Normal termination and EOF both commit output; a watchdog commits when the last non-empty PTY output has been silent for 150 ms, and a single hold lasts at most 1 s. Continuously arriving image chunks delay the quiet deadline, avoiding an intermediate state where the old image is deleted, the new image is incomplete and the cursor is temporarily hidden. Real-library tests confirm that native resize in 1.0.1 also ends the hold, after which the new size is published. The safety layer makes an independent renderer re-establish its snapshot after the callback consumes dirty state, so one renderer's state is not mistaken for another renderer's processed state. PTY and grid resize still happen under the same emulator lock, preventing new-size output after SIGWINCH from falling into an old-size grid.

### Terminal identity

Settings → Terminal exposes Terminal identity, defaulting to Termlevel and optionally set to Ghostty compatibility. The application wiring holds this preference, saves it with the workspace document, and reads it before creating a workspace so that a shell restored at startup uses the chosen identity. Documents missing the field, or carrying an unknown value, fall back to Termlevel and keep schema v1 and the existing layout.

Each `Sessions.open` passes the identity separately, and Rust maps it through a whitelist before spawning. Both modes set `TERM=xterm-256color` and `COLORTERM=truecolor`; the default sets `TERM_PROGRAM=termlevel` and the application version, while compatibility mode sets `TERM_PROGRAM=ghostty`, removes `TERM_PROGRAM_VERSION` and does not fake a Ghostty version. If none of the inherited `LC_ALL`, `LC_CTYPE` or `LANG` is UTF-8, `en_US.UTF-8` is added, preventing `pbcopy` in the session from writing OSC 52 Chinese text as MacRoman. Shell startup files can still override the environment. Changing the setting does not modify existing sessions, create or restart processes, or change Ghostty protocol parsing and the native renderer. The identity override is for client identification compatibility only; it does not represent the full capability of an emulated terminal or prove that real Codex Pets has passed acceptance.

## Scrollback history and cross-screen drag selection

A real terminal shows its history scrollbar inside Rust `session_view`; the viewport position is still managed by the single SurfaceController / Window, without adding a ScrollView or a JS grid copy. `scroll.rs` owns only scrollbar geometry and time-based edge-scroll speed. The thumb updates from the origin / count / rows of the published WindowSnap; dragging the thumb computes the origin inversely and goes through the controller's explicit reveal. The scrollbar overlays the terminal's outer right edge, and its width and margin come from `theme.json` (default 10 px hit width and 2 px right margin), independent of text padding and not deducted from the terminal's available columns. It appears on scroll, viewport change or pointer entry into the hit area, stays visible during hover / drag, and after leaving idles 800 ms before fading out over 180 ms. Show/hide changes reuse the existing Rust frame scheduling and do not change the column count. The alternate screen and a terminal with no history show no thumb.

Press immediately establishes a tracked selection in Ghostty; subsequent movement is captured by the NSH responder on the original grid gesture, so pointer moves and releases are still received after the pointer leaves the grid. The controller advances edge auto-scroll inside the existing 16 ms frame scheduling and updates the selection endpoint for the new viewport origin; speed increases with distance outside the top or bottom edge, and a per-round time cap avoids a catch-up jump after a pause. A mouse stopped at the edge keeps scrolling, returning to the middle of the grid reduces speed to zero, and release / cancel / hide / modal block / resize terminate drag tracking. The selection itself is still held by Ghostty; dragging the thumb only changes the viewport and does not clear the selection.

Coordinates are split explicitly: press and release use absolute history rows; hover and queued drag events use viewport-local rows, with the controller adding the origin exactly once. Program mouse reporting does not participate in host drag selection merging; when a host gesture starts by bypassing reporting with Shift, that gesture keeps ownership, so releasing Shift midway does not split the same drag into program events. Selection and history viewport are not modified during a synchronized output hold. Double-click for a word and triple-click for a line keep their existing selection semantics; there is no per-word or whole-line extension drag mode yet.

## Platform boundary

`SessionTerminal` embeds the application's own NSView through the NSH 0.6.0 Native Components public interface. `#[native_components(macos)]` in `src/lib.rs` registers it for both development and packaged hosts; no framework changes are needed. The measurement view is the only PTY resize input, and cell width and height come from the current Frame row / column counts; leftover pixels remain outside cells. The bottom-following origin is `line_count - Frame.rows`, and history retained by ED2 cannot be brought into the screen. Drawing rules and acceptance boundaries are in [terminal grid design](../design/terminal.md).

Snapshots are two-phase: copy Frame / history cells / images under the lock, then merge runs and build accessible text outside it. The Rust engine publishes a complete `Arc<Scene>`; the main thread briefly locks the scene slot to clone the latest Arc and then draws without the emulator lock. Across NSH properties only the slot ID and revision are exposed. The slot registry holds `Weak` references, and the publisher and native component are released with the mount; neither owns the session. Fonts, CTLine and CGImage stay in the main-thread renderer.

The native NSView draws image layer 0, cell backgrounds, image layer 1, search and glyphs, then image layer 2. Font and glyph layout use bounded caches, and images are reused by owned pixel identity. Runs are anchored to Ghostty column coordinates and clipped independently, share the main font baseline, and enable font ligatures; same-style ASCII segments synthesize ligatures without merging terminal cells. Continuous ligature shaping across style or selection boundaries, complex fallback, emoji and fine-grained accessibility still need extension or acceptance. A no-drawing Canvas Drawing supplies non-empty visible-row CanvasNode semantics to the NSH test model; the native container also has a whole-window text label without per-line views. The cursor is independent, and blinking does not redraw glyphs. Test fixtures can inject an independent terminal emulator.

The single native Input shares the grid origin, its position comes from the display snapshot's `input_cursor`, and its y coordinate is clamped inside the grid. During composition it shows marked text and system IME interaction; otherwise its text is transparent. Starting typing or composition requests bottom-following, delayed until the next publish during a hold. DECTCEM hiding the output cursor does not remove the input anchor.

`InputState` caches the composition process and commits only the final delta after it ends; cancelling deletes marked text without sending residual pinyin. The native value is confirmed first and then cleared through NSH `after_answer`, avoiding a Rust host property comparison that would skip an identical empty value; if the next composition has already started, it is not cleared. Normal input clears accumulated values that have not yet reached the platform, avoiding duplicates during fast typing. Terminal key bindings are suspended during composition, and Enter / arrow keys / Escape go to the IME. The NSH script fallback binding is active only when that session is active and Input is focused; the production local monitor is authorized by active state, avoiding lost keys when layout leaves the field editor unfocused. Command editing shortcuts do not occupy the workspace's new / close tab shortcuts.

Leaving the macOS field editor may cause AppKit to confirm the current marked text; the callback is still bound to the old `Arc<Session>` and does not forward to a newly active session. Mounting, hiding and focus do not own the PTY lifecycle.

Blank-cell backgrounds belong to the Ghostty safe wrapper: both active frames and history rows merge the packed cell's background content tag into the owned `Cell.style.background`. Glyph cell fitting belongs to the platform renderer: for supported line-drawing, block and terminal graphics characters, macOS uses built-in pixel glyphs ported from Alacritty, generated per device-pixel cell and cached as masks; normal text continues to use CoreText, and falls back to CoreText when a built-in glyph cannot be drawn. Sources, licenses and coverage boundaries are in [terminal grid design](../design/terminal.md); neither Session nor TSX maintains a glyph table.

`SessionTerminal` / `view.rs` only mount the surface, install physical input adaptation and query the NSH script input fallback through `platform`. `SurfaceController`, `Window`, `WindowSnap`, `paint::Scene` and search remain in the common Rust path. The publication channel is separate in `presentation.rs` and owns only an owned `Arc<Scene>`; the host resolves the slot by token, and each draw calls `Slot::latest()` to clone the latest scene and immediately release the lock. Native objects and the PTY are not part of this channel.

The current backend is selected at compile time; there is no dynamic plugin or generic renderer trait. Adding a platform requires:

1. Select the new backend in `platform/mod.rs` and implement `surface(scene, label)`, `install_input(session, active, cell_width, line_height)` and `synthetic_keys()`; a debug driver can implement the matching `track`.
2. Register a component with the same name, `termlevel.terminal-surface`, through the target platform's NSH Native Components entry. `src/lib.rs` is the only external wiring point for host registration; macOS uses `#[native_components(macos)]` → `platform::register_components`.
3. Use `presentation::element` to bind the scene producer closure and accessible-text closure; after receiving the `frame` property, the component resolves the slot through `presentation::resolve` and requests a redraw. Reuse the existing latest-only transport and release semantics, and never send cell grids to JS.
4. The platform host and renderer own their UI-thread affinity, font / image caches and resource destruction; the surface does not capture pointers or own the PTY. Common NSH input still handles IME submission, paste, layout and ordinary pointers, and platform input hooks only fill gaps in native event capability.

`platform/macos` is currently the only real implementation, internally split into the NSView host, CoreText drawing, the keyboard monitor and the debug probe. Other platforms have explicit unimplemented placeholder entries and cannot run a real renderer. The terminal surface boundary is the only part covered here; the Ghostty prebuilt library still supports macOS only, and the system clipboard helper, workspace native shortcuts and builds / packaging for other platforms still need follow-up work. These hooks do not imply that Windows or Linux build or pass acceptance.

### Font assets

Font resources are registered in one place by `Registry::assets(assets!())` in `src/lib.rs`: NSH loads them process-scoped before first layout, and packaging includes the original fonts, the OFL license, the author statement and the source verification manifest. The default terminal font chain is JetBrains Mono 2.304 → Sarasa Term SC 1.0.43 → system monospace; the font and version manifest is in `assets/fonts/`. New workspaces use this default, and existing font selections are not overridden. The renderer and cell-width / input measurement share the CSS family list and CoreText cascade; standard JetBrains Mono programming ligatures retain multi-cell advance.

## Lifecycle and concurrency

`SessionManager` holds sessions in Rust independently of the view. Only `Sessions.open` creates a process; `SessionTerminal` can only obtain an existing session by ID, and a closed or lost ID returns an error instead of implicitly recreating a process. IDs are generated by Rust and are independent of title, ordering, grouping, selection, PID and view position.

- Rebuilding the TSX workspace inside the same native host process rebinds still-live or exited sessions through `Sessions.list()`. Application start reads the persisted workspace document (see [workspace.md](workspace.md)), restores tabs in the saved order, groups and splits, and starts a shell in each tab's saved directory. A first start with no document stays empty and does not create a shell automatically.
- Persisted documents carry a schema version and save tab groups, tab order and pin state, the split tree, the selected tab, sidebar width and expansion state, font size, scrollback, font and appearance. Session IDs do not restore across processes, and old session IDs in the layout map to new sessions during restore; process PIDs are never written. NSH Storage is at `~/Library/Application Support/app.termlevel.desktop/storage.json` on macOS, and a corrupt document makes the app start with an empty workspace. Clipboard read permission is not persisted and resets on restart. OSC 7501 status, OSC 9;4 progress, OSC 22 shape and OSC 133 prompt state are runtime metadata and are not written; they are empty after an app restart, while UI hot reload recovers them from current sessions through `Sessions.list()`. The live directory is different: it is written as the tab's `cwd` through `liveCwd ?? cwd`, so a restart opens a new shell in the last directory.
- Destroying / rebuilding the TSX workspace and unmounting / remounting native terminal views do not close sessions. Rebinding reads the current Rust grid and state; it does not rely on an output copy or event replay in JS.
- Tab switching, group collapsing, renaming, reordering and theme changes preserve the same session ID. The workspace keeps terminal displays mounted by session ID; the layout tree decides which sessions are displayed simultaneously, and sessions not displayed are hidden, have hit testing disabled and are removed from accessibility traversal. The focused pane determines the single input target, while other visible panes keep refreshing.
- Explicitly closing a tab calls `Sessions.close`; closing a group closes its sessions one by one. A shell exit code of 0 (including Ctrl+D on an empty line) also closes the tab and pane without automatic restart. Non-zero exits and startup failures keep output and status.
- Closing the main window or quitting calls `Sessions.shutdown`. On Unix it ends the foreground process group and sends HUP to the shell so normal background jobs are cleaned up; if the shell has not exited after 50 ms it is force-killed. Daemons that detach from the terminal session are outside the recoverable-session model.
- Child inspection, termination and reaping share a control lock, avoiding signals to a recycled and possibly reused PID. After close, reader / writer cancel and the reaper reaps the child; app quit polls `Sessions.settled()` within NSH's 200 ms cleanup budget.

Reader, writer and reaper run on Rust worker threads. Unix PTYs use non-blocking I/O; the reader parses in 8 KiB chunks and waits for a readable event when no data is available (capped at 4 ms, to check closure and the synchronized commit deadline), without a fixed sleep between chunks that would accumulate input-echo latency for chunked image transfer. The writer uses a per-session FIFO byte queue: the total pending limit is 4 MiB (including the unfinished chunk held by the writer), a single input is limited to 1 MiB, and adjacent small inputs merge into write blocks of at most 8 KiB. The producer performs only a bounded copy and wakes the writer; it does not wait for the child to read. Keyboard, paste, mouse and protocol replies share ordering, and PTY short writes / WouldBlock retain the remaining data. An over-limit input is rejected as a whole, with an independent `inputWarning` indicating it was not sent and can be retried, without marking a running session as failed. The warning clears only after input accepted following the rejection is successfully written; in-flight writes from before the rejection cannot clear it falsely. Real read / write failures are still expressed by error / state. Close and process exit clear the queue and wake waiting threads.

Each session has exactly one 16 ms frame scheduler: each round observes the output revision and input generation at most once, and merges window, hover, host drag selection, selection, size and search reveal into at most one sample and publish. Event handlers only register invalidation and do not capture directly. Integer displacement and fractional remainder of sub-line wheel scrolling are both retained; reported wheel scrolling is no longer truncated to 32 lines per event but written in chunks without losing displacement. The workspace passes a low-frequency visible property; a hidden pane pauses frame capture, animation and search, and refreshes immediately when visible again, while an inactive but visible pane keeps drawing. The view refresh timer is destroyed with the view; session worker threads are not.

## Current capability boundaries

Real PTY, the preview provider and the Rust native grid view have all switched to Ghostty. Rendering is done by Termlevel's own AppKit NSView, and IME continues to use the NSH field editor; this is not equivalent to embedding the Ghostty application's GPU renderer.

- Application cursor keys, F1–F24, Shift / Ctrl / Alt combinations of arrow and editing keys, bracketed paste, focus reporting, title, bell, alternate screen, scrollback, reflow, color and size queries are connected.
- macOS provides physical keys, layout text, press / repeat / release and modifier events through an AppKit local monitor, then hands them to the Ghostty protocol encoder. The listener is authorized by the current active session and passes through to the external text editor for search, rename and settings; when the IME is needed it first obtains this session's field editor. Workspace Command shortcuts, Copy / Paste / Select All and IME marked text keep their existing ownership. Character keys on a non-ASCII input source still go to the IME until commit; without composing text, Enter, arrow keys and function keys continue to be encoded. NSH shortcut bindings pass through in the production path, avoiding two listeners competing for protocol keys. `scripts/nsh test` explicitly enables the script input fallback supported only in debug builds; native protocol tests explicitly disable that fallback and deliver events synchronously to a foreground AppKit window.
- Mouse click / release / drag / move / dual-axis wheel are encoded for the current DEC mode. Shift temporarily bypasses program mouse reporting to allow terminal selection / history scrolling; ordinary drag selection, double-click word, triple-click line and Alt rectangular selection are held by Ghostty tracked selection, and Cmd+C / Cmd+A target the terminal selection. OSC 8 targets are retained with the cell; links are underlined with a hint, and Cmd+click opens HTTP(S) / mailto.
- The native view supports Kitty inline RGB / RGBA / PNG images, drawing them with clipping, scaling, offset and three-layer z order from native placements. Pixels stay in Rust as owned RGBA, and the native renderer caches CGImage; animation updates use a native generation. Restoring a history image snapshot to the viewport preserves "follow bottom" semantics and invalidates other renderers' dirty-line caches. File / temporary-file / shared-memory mediums remain disabled.
- The cursor supports block / bar / underline, program-specified colors and blink mode; the output cursor is hidden during composition.
- OSC 52 / text clipboard callbacks are connected synchronously to the macOS system clipboard, limited to 1 MiB per operation. Copy is allowed by default; reading requires explicitly enabling "Read and write" in Settings and resets on restart. The callback uses `pbcopy` / `pbpaste` helpers with timeouts and does not wait for the AppKit main thread while holding the parser mutex, avoiding a main-thread / reader deadlock. Non-text MIME and primary / selection clipboards are unsupported.
- The actual system IME candidate list, cross-line selection copy, complex emoji and sustained multi-session output performance still need independent acceptance; complete Neovim / tmux compatibility is not claimed.
- Automated validation is complete for macOS arm64; x86_64 and Windows / Linux have not had application-platform acceptance.
- Layout and settings are persisted; an app restart still ends old sessions, saved tabs reopen with new shells, and PIDs cannot serve as recovery credentials. First launch shows a blank onboarding page.

## libghostty-vt Rust wrappers

Two workspace crates do not depend on NSH, PTY or the application's session management:

- `crates/ghostty-vt-sys` (package `termlevel-ghostty-vt-sys`): the official libghostty-vt **1.0.1** C ABI, original headers, pregenerated bindings, and the official macOS XCFramework verified by a fixed SHA256. The build extracts the target architecture's static library and does not require Zig. It supports building arm64 / x86_64 on a macOS host and reports an explicit error for other targets.
- `crates/ghostty-vt` (package `termlevel-ghostty-vt`): RAII handles, byte parsing, resize, text export, viewport snapshots with independent memory, protocol replies and metadata events, plus keyboard / mouse / focus / text paste encoded for the current terminal mode. After a threading-contract review the native handle is `Send` and remains `!Sync`; every access is serialized by `Session.emulator`'s Mutex. Ordinary synchronous C callbacks copy owned data; clipboard callbacks call a restricted `Send + Sync` host adapter and must not re-enter the terminal or wait for the UI thread. The PNG decoder is installed once via `Once` before any safe terminal is created, and output uses the allocator provided by Ghostty. A copied frame can be sent to the drawing thread.

These two layers own only terminal emulation state; Rust `SessionManager` continues to own PTY and processes. Production uses both layers, and the old Alacritty dependency has been removed. The safety layer includes the history window, search, color defaults, render hold, tracked selection, hyperlink targets, image placements with owned pixels and a synchronous clipboard adapter; the full C declarations remain in the raw API. Whole-viewport copying is the first interface and is not a final renderer performance conclusion.

Download, cache, offline build and version provenance are in [ghostty-vt-sys](../../crates/ghostty-vt-sys/README.md); safety-layer boundaries are in [ghostty-vt](../../crates/ghostty-vt/README.md). Neither package is published to crates.io.
