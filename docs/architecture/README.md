# Architecture

Termlevel is a macOS terminal workspace built as an NSH mixed project: TSX provides the workspace UI, and Rust owns processes, terminal state, parsing and high-frequency rendering. This directory describes current ownership and data paths. Directory ownership, dependency rules and validation entry points belong to [development.md](../development.md); outstanding work belongs to [roadmap.md](../roadmap.md).

## NSH mixed project

- `nsh.json` declares the Rust crate and the theme; `App.tsx` is the default TSX entry.
- The CLI, `nsh-core`, `nsh-base` and all `nsh-*` crates are pinned to the same version, currently 0.6.0.
- The UI uses the native macOS AppKit backend. There is no WebView and no web frontend.
- TSX runs in QuickJS and is drawn by NSH through the native platform. `termlevel/native` is an in-process Rust binding, not a network RPC.
- Type declarations are generated by NSH into `.nsh/types` and are not maintained by hand.
- Directories are split by responsibility; components do not get their own crate.

`App.tsx` mounts the workspace as the entry only. `WorkspaceRoot` reads the persisted document before mounting the workspace, and `WorkspaceApp` wires windows, menus, shortcuts, dialogs and session operations. TSX owns workspace UI and low-frequency metadata; Rust owns terminal streams, grids, parsing and high-frequency rendering. The Rust `SessionManager` holds sessions independently of UI mount lifetime, and only explicit session operations create or close processes.

## Component and data flow

```text
┌──────────────────────────── TSX workspace (QuickJS) ────────────────────────────┐
│ Sidebar · TilingCanvas · GroupEditor · FilesPanel · GitPanel / HistoryPanel      │
│ NotificationPanel · Settings                                                     │
└───────────────────────────────┬─────────────────────────────────────────────────┘
                                │ termlevel/native exports
                                │ workspace calls → Rust; low-frequency metadata → TSX
                                │ (in-process Rust bindings, not RPC)
┌───────────────────────────────▼─────────────────────────────────────────────────┐
│ Rust application crate (`src/`)                                                  │
│  SessionManager      session_view      Git reads        GitOps                   │
│  (PTY + processes)   (presentation)    (`src/git/`)     (explicit writes)        │
│  git_discovery       Files             Notifications                            │
└───────────────────────────────┬─────────────────────────────────────────────────┘
                                │
                 PTY + Ghostty terminal state        AppKit NSView terminal surface
```

- `SessionManager` owns PTY sessions, child processes and their worker threads. TSX calls explicit `Sessions.open`, `Sessions.close`, `Sessions.list` and `Sessions.shutdown` operations; it never owns a process. Terminal presentation lives in `session_view`, which binds an existing session by stable ID and draws through a native AppKit view.
- Git reads are centralized in `src/git/`, explicit writes in `src/git_ops/`, and repository discovery and directory watching in `src/git_discovery/`. The system `git` CLI supplies data; Termlevel does not embed a Git implementation.
- Files is a group-scoped tool view backed by `src/files/`. The Files architecture is documented in [files.md](files.md).
- Notifications are owned by `src/notifications.rs` in the host process, independently of session views.
- The terminal data path, session lifecycle and platform boundary are described in [terminal.md](terminal.md). Workspace state, tiling and persistence are described in [workspace.md](workspace.md).

The UI never receives terminal byte chunks or cell grids. Rust publishes bounded, low-frequency metadata to TSX, such as titles, run/exit/error state, bells and OSC-derived program status, progress and working directory.

## Preview mode

`TERMLEVEL_PREVIEW=1` explicitly enables a deterministic UI preview. It never executes system commands and never accesses real workspace storage. Git and terminal sessions show unavailable messages; the preview runs no background Git tasks and creates no terminal sessions, and it does not read or modify real notification history. Files is not called and no Git data is read for the file tree.

Preview tests enter this mode by replacing `Runtime.previewMode`. Real-session tests use separate native bindings and a workspace fixture, plus native fish acceptance through the default entry. Preview evidence is not real shell evidence.

## Theme

`theme.json` is the single design entry for colors, fonts, sizes and radii. Components use semantic classes and `token()`; they do not copy color values. After changing the theme, run `./scripts/nsh build` to regenerate token type declarations, then `./scripts/nsh check`. Do not edit `.nsh/types`. Sidebars and overlays are solid surfaces that express hierarchy with low-contrast separators, thin borders and light shadows, without glass or background blur. The theme does not own session lifecycle. Details are in [UI and theme](../design/ui.md).
